# Contributing

Thank you for considering a contribution.

## Before starting
- Search existing issues and pull requests.
- Open an issue to discuss substantial changes.
- Keep pull requests focused and explain the problem solved.
- Never commit credentials, access tokens, private keys, customer records, or org-specific secrets.

## Development expectations
- Follow Apex naming and formatting conventions.
- Write bulk-safe Apex; avoid SOQL and DML inside loops.
- Consider sharing, CRUD, and field-level security explicitly.
- Add positive, negative, and bulk tests where appropriate.
- Keep tests deterministic and independent of org data.
- Document prerequisites and behavior.

## Pull request checklist
- [ ] The change solves an identified problem.
- [ ] Tests are included and pass in a Salesforce org.
- [ ] No secrets or customer data are included.
- [ ] Documentation is updated.
- [ ] Breaking changes and limitations are explained.
